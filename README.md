# 食品工厂HACCP控制计划与偏差处置平台

独立 React 前端工程，采用 Fluent UI、Redux Toolkit、React Router、Vite 和 TypeScript。数据通过浏览器持久化，无需后端。

## 版本化处置流程

所有数据（控制矩阵、批次、偏差、处置版本、放行签字、审计）归属于一个整体“计划文档”，文档带单调递增的 `planVersion`，每次提交都是一个**完整新版本**。

- **矩阵改版联动处置**：控制矩阵的关键限值或纠偏措施变化时，关联控制点上**未关闭的偏差**保留既有证据，追加一个「等待重评」处置版本并锁定批次隔离，质量负责人重评后才重新进入复核；仅监控频率变化不触发重评。
- **已签字批次冻结**：批次签字放行时记录签字人、意见以及当时各偏差处置版本号与矩阵版本；此后矩阵改版不改写其状态、证据和签字。
- **并发不覆盖（乐观并发 CAS）**：两个浏览器窗口基于同一版本提交同一处置时，先到一方生效，后到一方的证据/签字/矩阵参数原样进入**冲突待办**（偏差版本链保留一条「冲突待办」+ 全局冲突收件箱），绝不覆盖对方；可在最新版本上「重放」为新版本，或「留档」备查。
- **可恢复的原子写入**：持久化采用“暂存 key → 主 key → 清理暂存”两段式写入，写入失败/崩溃后主 key 永远是上一个完整版本，不会留下半套审计；下次启动自动从暂存区恢复最后一个完整版本，失败操作可一键重试续接。
- **旧数据迁移**：首次打开无 `planVersion` 的历史数据时自动迁移，补齐每个偏差的处置版本链（登记/调查/复核）和影响范围，已放行批次补齐签字索引；原批次状态、偏差证据、放行签字、历史审计照旧可查，迁移本身留审计。
- **同源版本显示**：批次列表的「处置版本」列、偏差工作台的版本链时间线、追溯审计的矩阵版本/处置版本列取自同一份文档；追溯包导出包含完整版本链、签字与冲突处理。
- 跨窗口通过 `storage` 事件实时同步已提交版本；未关闭偏差（含等待重评）阻止放行。

## 校验

`scripts/flow-check.ts`（35 项）覆盖迁移、改版重评、并发冲突、双签字、写入失败与崩溃恢复；`scripts/thunk-check.ts`（32 项）用两个独立 Redux store 模拟双窗口并发的完整 thunk 流程：

```bash
npm run check:flows
```

端口为 `18464`。

```bash
npm install
npm run build
npm run dev
```
