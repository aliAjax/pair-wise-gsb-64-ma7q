# 食品工厂HACCP控制计划与偏差处置平台

独立 React 前端工程，采用 Fluent UI、Redux Toolkit、React Router、Vite 和 TypeScript。数据通过浏览器 localStorage 持久化，无需后端。

## 版本化处置流程

两个浏览器窗口可同时处理同一食品批次，所有处置（矩阵变更、偏差登记/调查/复核、批次流转、放行签字）都提交为**原子处置版本（V1、V2…）**：

- **矩阵变更联动**：关键限值或纠偏措施变化时，受影响的未关闭偏差**保留既有证据**并转入“待重评”，关联未放行批次维持隔离；已完成签字放行的批次按签字依据版本**冻结，不被改写**。仅监控频率变化不触发重评。
- **并发冲突待办**：两窗口基于同一版本同时提交，后到一方进入“冲突待办”（原意图、基准版本、对方版本完整保留），可**续提**（变基到最新完整版本重做）或**放弃**，任何一方都不能覆盖对方的证据或签字。
- **可恢复写入（WAL）**：提交遵循“前写日志 → 整版快照”顺序；主快照写入失败时不留半套审计，重新打开或点击“故障恢复”会从最后完整版本重做。顶部开关可模拟主快照写入失败。
- **旧数据迁移**：旧版数据首次打开自动补齐处置版本链、影响范围与历史放行签字补录；原有批次状态、偏差证据、放行签字与审计记录照旧保留可查。
- **同一版本三处可见**：批次列表、偏差工作台、追溯审计均显示当前处置版本；审计页提供完整版本链、每版影响范围（批次/偏差/控制点/冻结放行）与 JSON 追溯包导出。

## 功能

- 生产批次、放行状态（含冻结签字）、监测点与隔离范围。
- HACCP 流程图和控制矩阵编辑，记录关键限值、频率和纠偏措施。
- 偏差登记、原因与证据调查、待重评冻结、返工/报废分支、复核退回和签字。
- 未关闭偏差（含待重评）阻止批次放行。
- 完整版本化审计、冲突待办和 JSON 追溯包导出。

端口为 `18464`。

```bash
npm install
npm run dev       # 开发
npm run build     # 类型检查 + 生产构建
npm run verify    # 引擎不变量验证（50 项）
```

另可运行存储/恢复集成验证（29 项）：

```bash
node_modules/.bin/esbuild scripts/verifyStore.ts --bundle --platform=node --format=esm \
  --outfile=scripts/verifyStore.mjs --log-level=warning && node scripts/verifyStore.mjs
```
